## Decisions (section 4)
| Software protection scope | Owner, 2026-11-01: every part of the shipped software (C++ engine, .NET logic, AI models codenet/ocrnet/enhancer, product master and learned data) must resist reverse engineering and copying. The bar is economic and realistic — code that runs on a machine we do not control cannot be made truly impossible to reverse engineer or decrypt; the goal is to raise the attacker's cost above rebuilding the engine. This widens the earlier licence-only stance in LICENSING.md section 9 (no obfuscation/anti-debug) to add model encryption, build/package hardening and an anti-tamper runtime; where they differ on scope, section 18 (the later decision) governs. | REQUIREMENTS 18.1, 18.3; LICENSING.md 9 |
| Line safety on a protection failure | Owner, 2026-11-01 + requirements section 12: any protection failure (bad signature, failed decrypt, tamper/debugger detected, invalid/missing licence, file hash mismatch) must give a clean NG with a specific reason and tell the line — never a silent wrong read, never a crash that could pass a part, never a silent degrade to an unprotected model or unlicensed tool. Fail closed. Integrity faults make the case NG at once; entitlement faults (licence expiry) wait for the next start, never stopping a running batch. | REQUIREMENTS 18.5 (PROT-01..06); THREAT-MODEL.md 7 |
| Pre-release security self-test | Owner, 2026-11-01: "Claude Self Test for hacking before final version release each time without fail. If finds any gap then repair the gaps and issues... Claude can select appropriate model as per need." Before every final-version release, a security self-review / pentest is run against the threat model; gaps are repaired before shipping; a release may not ship while a known protection gap that could pass a bad part or leak the IP is open (hard release gate, tied to line safety). Written both as a requirement (18.7) and a process rule (CLAUDE.md rule 14); the same rule is kept in secure_me's CLAUDE.md (that copy handled by another session). | REQUIREMENTS 18.7 (PROT-10..12); CLAUDE.md rule 14 |
