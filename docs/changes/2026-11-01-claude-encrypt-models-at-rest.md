## How it works
- **At-rest container (`.vsenc`).** `BarcodeReading.Protection.ContentCipher` is AES-256-GCM: magic `VSENC1`, version, 12-byte nonce, 16-byte tag, ciphertext; the artifact's name is the GCM associated data, so a file encrypted for one role cannot be swapped for another. Decrypt verifies the whole file before releasing a byte and throws `ContentProtectionException` on any failure (wrong/missing key, tamper, truncation, wrong role) with no partial output.
- **Decrypt in memory, never on disk.** The engine gained buffer-load C APIs (`cr_load_model_buffer`, `cr_load_enhancer_buffer`, `vs_ocr_load_model_buffer`, `vs_ocr_load_second_model_buffer`) that build the net from decrypted bytes via `cv::dnn::readNetFromONNX(buffer)`. `CodeReader.LoadModel/LoadEnhancer` and `OcrEngine.LoadModel/LoadSecondModel` read through `ContentProtection.ReadArtifact`, which auto-detects an encrypted file by its magic, decrypts it with the licence content key and hands the bytes to the buffer API. A plaintext file (developer checkout) still loads unchanged.
- **Keyed to the licence.** The content key is never in the package. Each PC makes an RSA key pair at first start (`InstallationKeys`); the public key is sent with the licence check; the signed ERPNext answer carries the content key wrapped (RSA-OAEP-SHA256) for that PC (`LicencePayload.content_key`). `LicenceContentKeySource` unwraps it and hands it out only while the licence is active (offline grace included), and `LicenceService` installs it as `ContentProtection.KeySource`. A copy of the data on another PC, or on a PC whose licence lapsed, cannot decrypt it.
- **Product master + learned data.** `ProductStore` reads and writes through `ContentProtection`; the file name stays `.json` and the content becomes a `.vsenc` container when a key is present, plaintext otherwise. A protected product with no key does not load and the line is NG.
- **Build-time tool.** `dotnet/ProtectArtifacts` (`vs-protect`) reuses `ContentCipher`, so its containers are byte-identical to the runtime's: `vs-protect encrypt --key <k> ml/models/*.onnx` at package time; the plaintext stays on the build machine and is never shipped.

## Line safety (requirements section 12)
A missing or invalid content key, a tampered or truncated artifact, or an unlicensed/offline-expired PC makes every load throw and the station report NG with the reason. No partially decrypted model is ever used; no wrong product is read in the clear. Honoured now even though the protection spec (PR #220) is not merged yet.
