# Next generation of the reader: beyond Cognex and HALCON

Roadmap for the Barcode_Reading aggregation reader, 2026-10-27 (main at fbac9d0, after PRs #21 and #22). Method: a design study with seven independent angles (self-learning, imaging physics, decoding theory, speed and systems, learned perception, reliability, 1D codes), 44 ideas scored by three judges and the top ideas attacked by two critics each; this document keeps only what survived or was salvaged, plus the measurements made afterwards. The owner's aim: 100% of the selected codes inside the time targets, no wrong reads, and a reader that thinks differently from Cognex and HALCON.

## 1. Where the reader stands and what still fails

- 55 sample images, 1965 codes. Ample time (20 s) and 3 s: 1960 read (99.7%), 0 wrong. Line targets (100/300/500/600 ms), fresh reader per image: 1945-1948 (99.0-99.1%), 45-46 of 55 cases complete, median 52 ms per case on the M3 Mac. No number exists from the i7 line PC.
- Learning across cases, measured honestly on 2026-10-27 with `bench --carry` (one reader per product, each image decoded once): 1946 against 1945 fresh, i.e. nothing beyond run noise; carried across products regardless, 1878: what one product teaches (pruned steps, learned sizes, encodings) harms the next. Learned state must stay per product; the dashboard already makes a new reader per Start.
- The three hardest images (the 1.9 px/module TN excise labels, the 2.3 px/module shrink-wrap holograms, the dark 5-label case at brightness 12 of 255) were captured with the older 4096 x 2160 camera. On the MV-CS200 (5472 x 3648) at the same field of view the modules become about 2.5 and 3.1 px, inside what the reader handles today. The first action below is a re-shoot, not software.
- Unread with ample time (5): 4 QR at 1.9 px/module on the TN excise hologram label (version 1, EC M, 40 px wide); 1 bent, defocused cap (serial-run match 0.66 against 0.75).
- Lost to time (9): 2 of 5 faint labels at 100 ms; single codes on six 24-48-code cases that end within a few ms of target; a small first-case dip after each Start.
- Facts that shape everything below: bench noise is about ±2 codes, so most "+1 to +3" claims are inside noise; the earlier "learned reader" numbers (1951) came from `--runs N` on the same image, a leak, and are withdrawn; truth holds counts, not texts, so "0 wrong" is inferred from count uniqueness; 1D has zero images, tests or numbers; multi-frame has no real captures.

## 2. The thesis: how this reader thinks differently

Cognex and HALCON decode each symbol alone, from one image, with a fixed effort preset, and report a read once Reed-Solomon passes. This reader's edge is context and self-measurement.

1. **The case is the unit, not the symbol.** Codes on a case share a printer encoding, a serial run and a layout. Built: serial-run matching (match.cpp, dmmatch.cpp), known-content decoding (qrsoft.cpp knownDecodeQr, knownSoftDecodeDm). Proposed: the ERP's print list as the exact candidate set, a position-to-serial prior, the case grid for locating unread slots.
2. **Evidence, not constants.** Soft decoding with reserve symbols already refuses what it cannot prove. Proposed: a computed false-accept probability per read, read-back against serial neighbours, one written rule for every learned threshold.
3. **The reader measures its own lens and printer.** Built: learned encoding, module size, print growth (quality.cpp). Proposed: a per-zone PSF estimated from read codes, used for deblur and for rendering candidates.
4. **Time goes where it pays.** Built: learned step order and pruning per 4x4 zone. Proposed: a cost-aware scheduler on one persistent pool replacing the fixed 45/30/70/25% pass splits.
5. **Every read is a label.** A decoded code is exact module-level truth for this lens, ink and film; vendors do not own their customers' data. Proposed: a self-labelling data engine feeding tiny CPU nets behind a zero-wrong gate.
6. **Classic where classic is right:** optics, 1D scan-line projection, Wiener deconvolution, thread pools. Adopt, do not reinvent.

## 3. The self-learning, self-improving module

Three loops of rising cost, per product, one gate.

**Loop A, in-engine statistics (every case).** What: StepStats wins/tries per step and zone, qrModules, dmModules/dmSide, encoding, fullPassMs; new: ms EMA per step per (zone, blur, size) bucket, per-zone PSF, true/impostor score histograms for match and known-content. Persistence (the narrow form of #1/#44): `cr_get_learned`/`cr_set_learned`, a versioned blob saved beside `<product>.tuning.json` every 50 cases and at Stop, keyed by product code + version + camera-settings hash, reset on any change. Persist count tables, module sizes and PSF; the encoding only as a hint the first decoded code must confirm (decode.cpp:432 re-learns on disagreement); never codeMin/Max or symbolsPerCode (they re-learn in one case, and stale values drop regions). No count scaling, no nearest-product warm start (critics: inert and risky). Probe cases (every 20th) try steps in randomised order so position-biased win rates are not frozen.

**Loop B, line-side bandit (minutes).** TuningAgent as today plus a flat penalty when TotalMs exceeds the budget; exposure as a knob with brightness/saturation guards (#12) only after an offline brightness-scaling test shows an optimum.

**Loop C, data engine and nightly fine-tune (hours).** Signal: every read code (crop, corners, text, step, zone, exposure) with its module bitmap by re-encoding; hard positives from MATCH/KNOWN/GRIDFIT/LATTICE; unread crops as negatives. Saved by Station.SaveHardCase (extended to complete cases, capped per day) and autolabel.py. Consumers: the enhancer (its first real pairs), CodeNet, later ModuleNet. Retrain nightly on the line PC when 200 new pairs exist, a few hundred steps from the current .pt.

**Safety, one rule written once.** No threshold, prior or model moves on the line without: a floor; held-out, time-separated validation; a golden set (55 images plus line hard cases, with texts) at line budgets with reads >= old, wrong = 0, p95 time <= old + 5%; a shadow run on the i7; manual promotion (ModelRegistry.Promote) with the previous model kept; learned-state hash, model hashes and exposure in every case record; a single-thread deterministic replay mode; engine, models and state rolled back together.

**Reporting.** A Learning page grown from LineAdvisor.cs: per product the step order and pruned steps per zone, zone read map, learned sizes and encoding, PSF width per zone, thresholds with their false-accept estimate, drift events (CUSUM over brightness, sharpness, step shares, time), models in use with shadow results.

## 4. Ranked roadmap

All eight panel picks were refuted by both critics as stated; only salvaged versions appear. Costs assume one owner plus an assistant.

## 6. Reliability plan: zero wrong reads at scale

1965 codes cannot show anything below ~1e-3. Independent layers:

- **Measure.** Texts in truth; a wrong-read counter in bench; a standing adversarial set (rendered and photographed 1-digit serial neighbours, another product's labels, foil, random textures, RS-corrupted true codes) at every build; a 1e7-grid Monte-Carlo per soft path to measure the real false-accept per erasure count (#33 first step, half a day).
- **Evidence budget (#33).** Every accepting path returns log10 P(false) = RS term x parse fraction x attempts counted per region; accept iff <= 1e-9 (cr_params); summed per case in cr_stats. Replaces "4 reserve symbols because 2 once failed" with a number; loosens only where attempts are few. Not refuted; risk is over-conservatism on lattice (count only attempts that reached RS).
- **Read-back (#34).** Re-render every accepted text with the learned encoding, compare module LLRs against its 1-2-digit serial neighbours and the gap list; margin in bits logged; a low margin holds the case for review, never silently accepts. Fixes the DM match that is never verified (decode.cpp:1077-1081).
- **N-version rule.** A read from a low-evidence path (soft, lattice, match, known, frames) must be reproduced by an independent decoder or by read-back before it leaves the engine.
- **Reconciliation.** Every read against the ERP print list (R8); exact whole-history duplicates (R6).
- **Fail-safe and audit.** Watchdog on the decode thread; degraded mode when a model or state file fails to load; case records with engine, model and state hashes, exposure, per-code evidence, thumbnails for low-confidence codes, hash-chained later (#38); deterministic replay; territory switches in cr_params for lattice, multi-frame and under-resolved before any export, with PATENTS.md updated per PR.
- **Data governance.** Crops carrying excise serials stay on the line PC under a retention rule, out of the repository and off shared Macs.
- **Upstream.** For the owner's own labels: larger modules, EC Q/H, a clean quiet zone, no hologram under the code, and a verifier at the applicator; the excise print cannot change.
